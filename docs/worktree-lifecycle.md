# 工作树的生命周期：照 Codex 桌面版

状态：已实现（2026-11-04）。打开一个工作树已清理的任务只显示“恢复”，不会自动建回来；发消息、点“恢复”、交回工作树时才恢复。

## 来源

- Codex 桌面版没有开源。它的行为以官方文档为准：<https://learn.chatgpt.com/docs/environments/git-worktrees>（原 `developers.openai.com/codex/app/worktrees`，现已 308 跳转到这里）。
- Codex 开源仓库 `openai/codex`（读的是 2026-11-04 的 `021fccb`）里有桌面版和 CLI 共用的那部分：
  - `codex-rs/worktree/src/settings.rs`：设置项和默认值。
  - `codex-rs/worktree/src/lib.rs`：创建、列出、删除。
  - `codex-rs/worktree/src/paths.rs`：目录布局。
  - `codex-rs/worktree/src/metadata.rs`：工作树归哪个线程。
- 清理、快照、Hand off 的具体实现在桌面版里，开源仓库没有。文档也没写的地方，下面都标成“我们的设计”。
- 对比过的其它产品：Claude Code、t3code、orca 都没有一键本地合并，走的都是 PR。

## Codex 怎么做

### 创建

- 新建会话时，在作曲栏下面选 **Worktree**，然后选起点分支。
- 如果起点选的是“当前分支，带着未提交的改动”，这些改动会一并带进新工作树。
- 新工作树是**分离头指针**，不建分支，免得分支越来越多（文档原话：without cluttering your branches）。
  - 源码 `lib.rs` 里对应的是 `git worktree add --detach --no-checkout`，然后再执行 `reset --hard <sha>`。
- 目录放在 `$CODEX_HOME/worktrees/<4 位十六进制>/<仓库名>`（`paths.rs`）。
- 被 gitignore 的文件不会出现在新工作树里。仓库根目录可以放一份 `.worktreeinclude`，按 gitignore 的写法列出要复制的被忽略文件（比如 `.env`）。
  - 不复制符号链接，也不覆盖已有文件。
  - 被忽略的 `AGENTS.override.md` 不用列，会自动复制。
- 可以选一个“本地环境”，用来运行 setup 脚本。

### 两种继续方式

**1. 留在工作树里干**

- 会话标题栏有个 **Create branch here**，用来给工作树建一个分支。
  - 弹窗标题是 **Create branch**，有一个“分支名”输入框。
  - 分支名有可设置的前缀，默认 `codex/`。
- 建了分支后，用户自己提交、推送、去 GitHub 开 PR。
- **Open** 按钮在 IDE 里打开工作树。

**2. Hand off 到本地**

- 标题栏点 **Hand off**，会话就挪到本地检出。
- 弹窗标题是 **Hand off thread to local**。正文说的是：在本地检出切到分支 `codex/xxx`，并把这个分支从工作树上摘下来。
- 反方向也可以：本地的会话 Hand off 回工作树，回到它原来那个工作树。
- 每个会话始终绑着同一个工作树。
- Hand off 走的是 git 操作，被忽略的文件不会跟着走。
- 文档专门解释了原因：同一个分支同一时间只能在一处检出。要在本地看工作树里的成果，正确的做法是 Hand off，而不是两边检出同一个分支。

**没有合并按钮。** 合并要么在本地自己做，要么在 GitHub 上合 PR。

### 保留和清理（重点）

- 文档原话：“Worktrees use a lot of disk”，因为每个工作树都有自己的一份仓库文件、依赖和构建缓存。
- 默认**保留最近 15 个**由 Codex 管理的工作树。数量可以改，自动删除也可以关。

开源代码里的设置项（`settings.rs`）：

| 键 | 默认值 | 规则 |
| --- | --- | --- |
| `git-worktree-root` | `$CODEX_HOME/worktrees` | 必须是绝对路径 |
| `worktree-auto-cleanup-enabled` | `true` | 布尔值 |
| `worktree-keep-count` | `15`（`DEFAULT_WORKTREE_KEEP_COUNT`） | 正整数，0 会被拒绝 |

- CLI 用同一个目录，但**不做**自动清理（`for_cli` 把 `auto_cleanup_enabled` 设成 false）。

这几种工作树不会被自动删：

- 置顶会话的工作树。
- 会话还在运行中的工作树。
- 旧版本留下的“永久工作树”。

两种情况会触发删除：

- 会话被归档。
- 工作树总数超过上限，从最旧的开始删。

删除前会**先存快照**。删除后再打开这个会话，会看到“恢复”的选项。会话本身一直留在历史里。

### 文档没写的

- Hand off 时，未提交的改动怎么带过去。
- 本地检出不干净、或者在别的分支上时怎么办。
- 快照里存了什么、存在哪里。
- 清理在什么时候执行。
- “最近”按什么排序。

这些都由我们自己设计，下面会标出来。

## 实现前的状况

| 项 | Codex | 我们 |
| --- | --- | --- |
| 新工作树 | 分离头指针，要用时再建分支 | 每个任务都建一个 `aiwb/<id>` 分支 |
| 起点 | 可以选分支，可以带上未提交的改动 | 只能从源目录的 HEAD 开始，不带改动 |
| `.worktreeinclude` | 有 | 没有 |
| 建分支 | Create branch here，前缀 `codex/` | 没有 |
| Hand off | 工作树和本地之间双向挪动 | 没有 |
| 数量上限 | 默认 15，可以改，可以关 | **没有上限**，只在删除任务时手动删 |
| 归档 | 删工作树，删前存快照 | 只停掉 Agent，工作树留在磁盘上 |
| 快照和恢复 | 有 | 没有 |
| 设置 | 目录、自动删除开关、保留个数 | 没有，目录固定是 `<数据目录>/worktrees` |

本机实测：现在只有 1 个工作树，就占了 577 MB。照这个量，15 个大约 8 GB；如果不设上限，用一阵子就会到几十 GB。

## 方案

原则：能照 Codex 的就照 Codex。文档没写的地方，下面标了“我们的设计”。

### 1. 保留和清理（先做）

**设置**放在 daemon 的 meta 表里，和“任务文件夹”的做法一样：

- 工作树目录：默认 `<数据目录>/worktrees`，必须是绝对路径。
- 自动清理：默认开。
- 保留个数：默认 15，最少 1。

**哪些工作树算进上限：** 只算工作台自己建的。判断依据是 `ai-workbench-worktree.json` 这份记录；所有项目的工作树合在一起算。

**受保护、不会被删的：**

- 置顶任务的工作树。
- 会话正在运行或在等输入的工作树（交给了项目目录的任务在别处跑，不算）。
- 还有不止一个没归档的分叉任务在共用的工作树。
- 父任务还在运行的子任务的工作树：父任务可能还要看它的改动。

**什么时候删：**

- 用着它的任务都归档了。
- 新建工作树、归档、改设置之后，以及 daemon 启动时，在后台检查一次。总数超过上限时，按任务的“最后活动时间”从旧到新删，删到不超过上限为止。刚恢复的工作树算刚用过。（排序方式是我们的设计。）
- 先不拿锁挑出要清的，真要清某一个时再拿工作树锁、重新核对一遍：挑出来以后有人用过、取消了归档、置顶了或者跑起来了，这一轮就不清。
- 工作树任务的会话从拿到目录到 CLI 接上一直拿着工作树锁，清理和交接要么等它接上（之后能停掉它），要么做完了它再按新状态接上。

**清理会丢的：** 被忽略的文件（比如在工作树里改过的 `.env`、本地数据库）和工作树里嵌套的 git 仓库不进快照。恢复时被忽略的文件按 `.worktreeinclude` 从项目目录重新复制，是项目目录里那一份。

**删任务：** 删除工作台建的工作树时，记录里的旧版 `aiwb/<id>` 分支只有还指着工作树的提交时才删；往前走过（交接后在项目目录里提交过）就留着。

**加锁：** 分叉和删除任务也要先拿工作树锁，不会分到一半被清理、或删出半个工作树。

**不删的：** 没有任务指着的旧工作树（用户删任务时选了保留工作树，或者旧版留下的）不计数也不清理。那是用户明确留下的，自动删可能丢东西。

**快照（我们的设计）：** 删除前，把工作树的完整状态存成一个提交，不碰用户的 index 和分支。

1. 每次用一个独立的临时 `GIT_INDEX_FILE`，依次执行 `read-tree HEAD`、`add -A`、`write-tree`。`add -A` 遵守 `.gitignore`，所以 `node_modules`、构建产物这类被忽略的大目录不会进快照。省磁盘本来就是清理的目的。
2. 用 `commit-tree <tree> -p HEAD` 生成提交，再用 `update-ref refs/aiwb/snapshots/<任务 id>` 记下来。
3. 任务上记下：快照的引用、原来的 HEAD、原来的分支名（如果有）和工作树路径。
4. 清理**不删任何分支**：分支上可能有交接后在项目目录里提交的东西。
5. 先把快照记进任务（标成已清理），再删目录；删目录只用一次 `git worktree remove --force`，不硬摘登记、不 `prune`。git 删不掉（工作树还在用，比如被编辑器打开、被锁住）就撤回标记和快照，这次不清，目录原样留着。登记摘掉了才清残留，删不干净的在恢复时再清。
   - 中途停掉（daemon 被杀）时，任务标着已清理、目录还在：恢复时发现原路径上还是一份登记着的完整工作树，就直接接着用它。
6. 只剩快照的任务，删除前按“有未保存的改动”提醒。用户确认连工作树一起删时才丢快照。

**恢复（我们的设计）：** 打开一个工作树已清理的任务时，作曲栏上方显示“工作树已清理，发消息时自动恢复”和“恢复”按钮。只是打开不会恢复：读模型列表、权限菜单、推目标这几步在工作树已清理时都不启动 Agent。

1. 原路径上还是一个登记着、完整的工作树就直接接着用，不动里面的东西。否则只摘掉这一份的旧登记（不用 `worktree prune`，免得把暂时不在的其他工作树也摘掉），清掉残留，再在原来的 HEAD 上执行 `worktree add`。
2. 原来的分支还在、并且还指着原来的 HEAD，就检出这个分支；分支不在了就按原名重建；分支已经往前走了就留在分离头指针。
3. 执行 `read-tree -u --reset <快照>`，再执行 `reset -q`。这样快照里的改动回到“未提交”状态，删掉过的文件也会还原。
4. 按 `.worktreeinclude` 重新复制被忽略的文件。
5. 恢复回原路径，会话的工作目录不变。记好“已恢复”之后才删快照引用，中途出错还能再恢复一次。恢复后给 Agent 补推一次目标。
6. Agent 没有存过模型列表时，已清理的任务打开后模型菜单是空的，恢复后才有。看“上一轮”的差异也要先恢复。
7. 快照从检出自己的 index 拷一份开始写，带着文件的时间戳缓存，大仓库里不用把每个文件重新算一遍。

### 2. 创建

- 默认改成分离头指针，不再给每个任务建 `aiwb/<id>` 分支。已有的任务保留原分支，不迁移。
- 新建任务打开“在新的工作树中运行”后，分支芯片换成“起点”选择：可以选任意本地分支；当前分支有未提交的改动时，多一项“带上未提交的改动”。选中的是具体分支名，草稿以后再发时不会跟着项目目录换分支。
  - 带改动只在起点就是项目目录当前分支时生效。做法：在项目目录里用和快照相同的方法生成一个提交，再在新工作树里执行 `read-tree -u --reset` 加 `reset -q`。项目目录不受影响。
- 支持 `.worktreeinclude`：只复制被忽略的路径，不复制符号链接，不覆盖已有文件，自动带上 `AGENTS.override.md`。列文件时 git 会走一遍没跟踪的目录，大仓库里新建和恢复会慢一些。
- 换项目时草稿里选的起点分支不带过去。

### 3. 建分支

- 工作树会话的分支芯片菜单里有“创建并检出新分支…”。工作树还没有分支时，分支名预填 `aiwb/`，可以直接改掉前缀。
- 实际执行的是在工作树里 `git switch -c <name>`。

### 4. Hand off（我们的设计，Codex 文档没写具体做法）

入口在作曲栏上方：工作树任务显示“交给项目目录”，交过去以后显示“在项目目录 · 交回工作树”。侧边聊天里不显示。整个交接拿着工作树锁，期间不清理、不恢复，会话启动也要等交接完。

只有声明了 `supports_workdir_move`（换目录后能接着原来的会话）的 Agent 能交接：Claude、Codex 实测过；Cursor 走 ACP，`session/load` 本来就带 `cwd`，按协议打开，本机没有 Cursor CLI，**还没用真实 CLI 实测**。交给项目目录的任务只能换到有这项能力的 Agent。

**从工作树到本地：**

1. 前置检查：
   - 这个任务没有回合在运行。同一个仓库检出里干活的其他任务（直接在项目目录的、交给了项目目录的，包括同一仓库的子目录项目）也没有在跑，因为要切这个检出的分支。归档了的任务不算。
   - 同一个仓库检出一次只能有一个任务交给它（交过去后归档了的也算，它的分支还占着检出）。
   - 没有没归档的分叉任务共用这个工作树。
   - 本地检出必须干净，否则拒绝，并列出有改动的文件。我们不替用户 stash。
   - 工作树必须有分支。没有就先起一个分支名（预填 `aiwb/` 加标题）。
2. 工作树被清理过就先恢复。停掉任务的会话，关掉它的终端。同一个检出里其他闲着的任务，接着的 CLI 也停掉：交接期间它们要发消息得重新接上，接上要等交接做完。
   - 切分支、铺文件、清理这些改用户检出的命令按用户自己的 git 配置跑（钩子、LFS 照常），LFS 文件不会变成指针。
3. 在工作树里，把未提交的改动写成提交，挂在 `refs/aiwb/handoff/<id>` 上（出错时改动不会变成没人指着的提交，错误信息里写着这个引用）。然后 `switch --detach`，把分支让出来。
4. 记下本地当前所在的分支和提交，回头要用。然后 `switch <分支>`，再用 `read-tree -u --reset` 加 `reset -q` 把改动铺到本地。工作树恢复成干净的检出。
5. 出错时两边都放回原样：为这次交接新建的分支也撤掉。成功后删掉交接用的引用。起名对话框等交接做完才关，失败原因显示在对话框里。
6. 任务记下交接信息。Agent 会话的工作目录换成项目目录，时间线里记一行“已交给项目目录，分支 X”。

**从本地回到工作树：**

- 项目目录还在交接的分支上：上面的步骤反过来做。本地切回第 4 步记下的分支（这个分支删掉或改名了就回到记下的提交）；工作树重新切到这个分支，铺上改动。项目目录清理失败（文件被占用）时把改动铺回项目目录，错误里写着改动存在哪个引用。
- 项目目录是共用的，交出去期间别的任务在那里改的、没提交的东西也会一起带回工作树。时间线里列出带走了哪些文件。
- 项目目录已经离开这个分支（比如切回主分支去合并了）：不动项目目录，工作树检出这个分支接着做；分支删掉了就留在原来的提交上。时间线里写明项目目录没有动。

**交给本地之后**，工作树还在磁盘上。它照样计入上限，可以被清理（清理前存快照，不停在项目目录里跑的会话）。

**分叉：** 从交给了项目目录的任务分出来的任务，直接在项目目录里干活，不共用那份交接记录。

**合并：** Codex 没有合并按钮。Hand off 之后，分支已经在本地检出，用户用自己熟悉的方式合并或开 PR。

### 真实 CLI 验证（2026-11-04）

- **Claude**（2.1.312）：在目录 a 用 `claude -p` 开会话，再到目录 b 用 `--resume <id>`，记忆还在，Agent 报告的工作目录是 b。适配器本来就用新的工作目录启动进程并带上 `--resume`，不用改。
- **Codex**（codex-cli 0.165.0）：在目录 a 用 `codex exec` 开会话，再到目录 b 用 `exec resume`，记忆还在，`pwd` 是 b。app-server 的 `thread/resume` 支持 `cwd` 覆盖（`codex-rs/app-server-protocol/src/protocol/v2/thread.rs` 的 `ThreadResumeParams.cwd`），适配器现在恢复线程时都带上当前工作目录。
- 工作台里实测：交给项目目录后发消息，Codex 在项目目录里跑；交回后回到工作树。
- **Cursor**：本机没有 Cursor CLI，没实测。适配器在 `session/load` 时传当前工作目录，按 ACP 协议应能换目录接着会话；装上 CLI 后要补测。
- 看板卡片和子任务回报里的分支按同一条规则算（daemon 的 `task_branch`）：交给了项目目录时是交过去的分支，否则直接读工作树的 HEAD 文件（不起 git 进程），清理掉了就是清理时的分支。分离头指针时不显示。

## 已定

- 没建分支的工作树，分支芯片写“基于 <起点分支>”（没有起点分支时写短 SHA）；建了分支就显示分支名。在工作树里建分支时，名字预填 `aiwb/`。（2026-11-04）
- 不做本地合并，照 Codex：Hand off 到本地后由用户自己合并或开 PR。（2026-11-04）
