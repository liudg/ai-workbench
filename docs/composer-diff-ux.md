# 作曲栏模式、默认模型和差异视图

这些行为和 Codex app-server / TUI 对齐。预览页只渲染同一套逻辑，不代替协议调用。

## 计划和目标

- 作曲栏同时只显示一个模式芯片。本地目标草稿优先。服务端目标和计划都在时，后发生的那条事件赢。
- 选「计划」会退出目标（有已提交目标时调用 `thread/goal/clear`），再 `set_collaboration_mode(plan)`。下一次 `turn/start` 带 `collaborationMode`。
- 选「目标」会把协作模式设回 `default`，芯片表示正在写目标。提交时走 `thread/goal/set`。关掉芯片即退出；已提交的目标会被清除。
- 打开会话时如果计划事件比目标新，只显示计划芯片，不主动清掉已经存在的目标。关掉计划后目标芯片还会出现。反过来，界面在显示目标时会把协作模式设回 `default`，避免下一回合仍以计划模式发出。
- `supports_plan` / `supports_goals` 为假时，`@` 菜单该项不可选，不留一个只改外观的芯片。

## 首次进入的模型

显示顺序：用户在这次会话里选过的模型、已打开线程的模型、`config/read` 的 `model` 和 `model_reasoning_effort`、目录里 `isDefault` 的模型。最后一项只用在配置已经读到、且里面没有 `model` 的时候。

`config/read` 失败时按钮写「未读到 CLI 默认模型」，不用目录第一项或 `isDefault` 冒充 CLI 默认。加载目录不会调用 `setTuning`，所以不会把界面上的默认写回会话、盖掉 CLI 配置。

## 目标状态栏

只在目标模式出现，在作曲栏卡片上方一行，不画进圆角输入框里面。文案跟 TUI `goal_status_indicator_line`：有 token 预算时显示 `12.5K / 50K`，否则显示已用时间。用量字段没从 `thread/goal` 来就不补 0。不在目标模式时这一行不出现。

## 差异

- 「隐藏空白字符」只拿掉和另一侧只差空白的那几行。拆行、改了内容的行仍留下。文件仍留在列表里，统计仍是原来的 `+N −M`。不因为这次勾选去重新请求 `git diff -w`。
- 收起：每个文件一行，路径和 `+N −M`。点这一行或箭头展开该文件的 hunk。
- 「展开全部差异」：每个文件展开自己的 hunk，不是整份源文件。
- 「加载完整文件」仍是单独的开关。勾上并且文件已展开时，统一 diff 才补上未改动行。
- 新增文件和删除文件的协议正文不是 unified diff。按 Codex `diff_render` 把正文行画成绿色新增或红色删除。只有新增或只有删除不算空 diff。
